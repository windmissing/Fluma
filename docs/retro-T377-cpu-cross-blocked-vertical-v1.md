# T377 方案复盘

2026-11-06，designer。主稿 `algorithm-T377-cpu-cross-blocked-vertical-v1.md`。CPU 参考 P3，不使用真机。

| 候选 | 取舍 |
|---|---|
| 只解除旧 y/vy 保留，直接用 predictedY | 目标床高已经进入 predictedY。拒绝跨列时可能把粒子抬到目标床高度，破坏源列约束。 |
| 拆分碰壁时刻再对余时重积分 | 需定义子步内多次重力/拖曳取样和横向重试，会扩大到新的积分器与时间顺序。本卡沿原半隐式候选，横向碰壁吸收速度。 |
| 原列触床后同一 T4 行立即补 T3 | 会增加未进冻结分母的请求，或提前把未确定的 T3 计入比例。也会改变后续 ID 的预算和床面 guard 次序。 |
| 源列纵向一次推进，触床锁定，下一成功子步走 T3 | 选用。保留原请求、费用和阶段顺序。新行为引入最多一子步的触床等待，guard 或预算仍可限制最终退役。 |

现行冻结源床命中已有正常 T3。新难点是 collect 之后源床可能因先行落床或后续场通道变高。设计区分行内床与最终床，在外层提交前用有界清单处理余量。由于现有 M2 projection 在场通道前采样，新增尾证据需在最终床准备好后对拍。工程应明确 writer 闭包和回滚归属，避免重复全池审计放大 CPU 参考线耗时。

T369 两份原档给出定位所需位型。模型只读权威窗并检查算术候选、约束和票据守恒关系。实际 Hot 写者、V2 缓存、宿主退款、注错回滚与设备效果仍需按主稿矩阵分别验证。后续由 architect 落工程合同，developer 实施并自测，tester 补独立和真机证据。
