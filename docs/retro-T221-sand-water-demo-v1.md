# T221 方案复盘 v1

2026-10-28，designer；路线 `sand-water-demo-flight-v1`，不使用真机。只交算法/独立测试合同及architect任务书，非产品验证。完整方案 `algorithm-T221-sand-water-demo-v1.md`。

## 候选与选型

1. **直接增加W并画水流：REJECTED。** 当前Source确实只加floor(x)列W，y仅作床内拒绝；加条水柱不能补足真实飞行/到达时序，源成功即入W会先扩散后“画到达”。
2. **视觉延迟、到达才调用旧A源：REJECTED作为目标8正式路线。** 可以保留一张尚未成功请求表，但屏幕上水的质量尚未进入权威总水账；暂停/切源/容量变化/重复请求需要另外定义待准入的外部物质，且arrival前不是已成功在途水。若选择这种不同体验必须另合同，不能冒本路线的成功注入。
3. **水做SPH/欧拉全网格：DEFERRED。** 用户未要求飞溅/压力/滴间相互作用；引入邻域/压力迭代和新边界，无法作为最小DEMO演进直接复用现B。
4. **每个水包独立外部owner：REJECTED。** W/在途物质/源账分散，跨owner到达要双提交；source成功后step失败与同帧proof变难，且违反复用同一目标7库存。
5. **同owner有界点水包＋末尾到达：SELECTED。** 明确J不是W副本；支持真实位置与模拟时序，源/在途/到达有同一账与root，局部容量O70、一次接触排序，无逐事件整池放大。代价是V2总水审计/容量改变，必须新run和独立回归，不能宣传纯等价优化。

## 推导中修正的风险

- 初想仅给水包“保留终点列容量”不成立：倾角跨列会改变终点、床流/其它源也改变空余。改为当前列J保留，所有水沙writer都参与；保守阻挡真实记录，不偷偷扩容。
- 原V1水审计ΣW≈initial+I不适用J>0。不能把产品audit失败简单豁免；显式V2ΣW+Σ包审计，旧V1保留。
- ARRIVE的名义J−m/W+m不保证RN exact量不变；实际W无写/容量/守恒失败需WAIT或root失败，不能丢小包/补尾凑账。
- 末尾按ID到达可能让晚到达的低包抬面吞没已跳过的高包；改为一次(column,y,id)排序收尾，不逐次重扫，明示O(Kw log Kw)。床/水面下降释放保留原y，不假瞬移落低面。
- 为复用B40而把waterId塞sandId会破坏来源/逐流ordinal；采用独立48行＋统一顺序tape，replay全root，独立oracle另持。
- “停止后W必须不变”在J>0时错误；应验证总水守恒、无新成功，W可随已成功J到达增长。
- 双侧扩散需要水平、两侧可接收；倾斜/墙/沙脊/J保留可单向，不能用同一视觉断言误判。
- T219真实存在两处设计缺口。本文补齐面积覆盖/线性预乘高光与显式±30接受策略；shake仅诊断不是平移激振，保留用户目标中姿态改变重力的部分，并明确不足而非暗加力。
- V2不同于T207干场数值V2：明水W不得设0，canonical P不能替换成exact-RN；只有局部辅助容量用70limb。
