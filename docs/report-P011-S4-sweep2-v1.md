## 一、诊断结论（先诊断再扫）

**首轮 60 组全部只跑了 1 个 step。**

根因：`updateMetrics` 的 dormant 判定只观测表层（悬浮/shake/坡度/水面）。S4 激活的场
在第一个 step 后表层静止 → dormant=true → step 早退 → 后续 119s 全部静默冻结
（totalUsed 停在 0.0337 不动）。首轮报告的「ampPx−amp0Px=0」不是机制不动，是
**harness 根本没在跑**。

证据链：单组 k=0.05 中途快照显示 t=1s/10s/60s/120s 的 totalUsed 完全相同
（0.033699889249641665，逐位一致）；step 1 即返回 dormant=true。

修复（调度层正确性，非通道机制改动——applyDeepCreep 零改动）：
`deepCreepRouteActive() && deepCreepHasDrive()` 时 dormant 保持 false。
`deepCreepHasDrive()` 是 O(cols) 轻量探针，镜像候选生成规则（D>0 且双端库存足）。

修复后同参数 120s：totalUsed 0.0337 → **171**（5000 倍），max|Δbh| 达 2.96 单位。

## 四、机制域分析（交 designer/architect 判定项）

1. **语义**：S4 是衰减器（所有组合 ratio<1）——保留分选界面的起伏结构并缓慢
   磨平；平界面零通量（对称性闸门=正确行为，非 bug）。
2. **速率上限**：k=0.2、D~5 时单子步单对 q~0.017；300s 理论上限 ~490 单位，
   实测 328（预算共享）。5px 界面的衰减时标 ~分钟级——匹配开题「数十秒-分钟窗」。
3. **域外 k**：磨平 73px 初态需 k~2-5（上限的 10-25 倍）——**architect 域修订
   决策点**（若产品需要快重塑），非 sweep 参数问题。
4. **μ_y 归一化**：p_eff=(S_i+S_j)/2≈250 使 μ_y·p_eff≫Δbh；建议下版
   p_eff/S 或逐单位化——**architect 代理升级决策点**。
