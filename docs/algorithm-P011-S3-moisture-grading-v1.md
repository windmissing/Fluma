# P-011 S3：沙水湿度分级设计 v1

日期：2026-10-23。责任：designer。状态：**DESIGN_OPENING / TWO_RELEASES / NOT_IMPLEMENTED / NOT_CALIBRATED**。技术路线：`s3-moisture-profile-v1`（保底首版）；升级路线：`s3-local-seepage-v2`（产品终态，本文只冻结接口与责任，不作详细求解器设计）。依据用户 15:33/15:38 裁决：**水渗透是产品意图**；分两版仅为工程风险对冲，首版交付后须继续推进局部渗透。本文纯设计，不改物理代码、用例、冻结锚点或 26°/20° 的历史来源。

## 1. 范围与论文边界

首版在**同一列的不同高度**保留不同湿度，底部更湿；真实加水量改变整列湿度水平，因而改变局部起停角及倾斜响应。湿度是连续物理代理场，**不把“水位降后露出双色干湿层”当主效果**。渲染以后可以只读该场显示材质变化，但首版效果验收先看材料动态，不用颜色差代替仿真差。

[Su 等，*Real-time Height-field Simulation of Sand and Water Mixtures*，§3.3.3、Fig.3](https://kuiwuchn.github.io/RTWaterAndSand.pdf) 的分段式直接给**内聚系数** `c_c(φ)`，不是双角阈值公式；其 §3.3.1 的外摩擦还经水浮力改变法向力。论文的 `φ=(h^w+h^wbar)/(h^w+h^wbar+h^s)` 是所用沙水混合体积中的**水体积分数代理**；论文把它用于近似饱和度，不能等同于我们尚未建账的“孔隙水量/孔隙容积”。原文图示 pendular→funicular→capillary、少量水桥增内聚、饱和后内聚趋零；作者仿真取 `φ1=0.2, φ2=0.25, φ3=0.33`，这些**不是 P-011 的可移植分段点**，原文“pendular 通常<10%”也不是把项目阈值固定为 0.1 的证据。下文从 `c_c` 转成 `θstart/θstop` 属**项目新闭合 / 待定标**，不声称论文已证明该角度映射或真正成团力。

先明确原文函数的结构，避免“分段线性”被改写成任意单调湿度倍率。令 `0<φ1<φ2<φ3`、`c0,c1,c2≥0`：

```text
c257(φ) = c0 + φ(c1-c0)/φ1,                   0≤φ<φ1
        = c1 + (φ-φ1)(c2-c1)/(φ2-φ1),       φ1≤φ<φ2
        = c2(φ3-φ)/(φ3-φ2),                 φ2≤φ≤φ3
        = 0,                                 φ>φ3
```

第三段降至零；第二段是否严格恒定取决于 `c1,c2`，论文文字描述“近似恒定”，公式仍允许两者不同。首版用同拓扑的 `C(s)` 候选，但 `s` 是下节有效湿度代理，分段点/幅度全部重新标定。**不要**把原论文 `c0,c1,c2,φ1…φ3` 数字抄成产品默认。

## 2. 首版状态表示选型：逐列 × 逐高度格

**表示澄清（用户 2026-10-23 追问）**：现有高度场的 `bh/bl/mh/ml` 只给每列几个**材料层高度/库存**，并未记录“同一层的下部湿、上部干”。不能从这些高度凭空读出局部湿度。S3 需在每列额外叠一个纵向属性数组：高度场负责沙子占据到哪里，`s[c,k]` 负责占据区中第 `k` 个高度格的湿度。它是 **128 列 × K 层的辅助标量场**，不是增加 K 条可移动的沙层界面，也不求解 K 层的速度/动量。只给现有四个材料字段各附一个湿度值虽更省内存，但厚层内部会被迫等湿，无法表示湿润前沿，故不选。当前代码没有这个数组；这是待实现的新状态。

```text
同一列 c：  waterTop ─ 水面
                 [空/自由水]          m[c,k]=0，无沙湿度
             S ─ 沙顶
                 [上部沙：s[c,k高]]
                 [下部沙：s[c,k低]]     可有 s下 > s上
             0 ─ 容器底
```

首版按高度与真实全局水量生成这些格的值；所以“同一高度的两列”在同一水量下通常同湿，**还没有**局部湿斑或真实湿润前沿。高级版仍读写这些 `(c,k)` 格，但每格加孔隙水库存与上下/左右通量后，才允许同高度不同列的湿度因渗透而独立演化。这个区别须在 UI 和验收报告里说明，不把数组存在误称为已经实现渗透。

| 候选 | 首版成本/可表达性 | 升级局部渗透时的代价 | 裁决 |
|---|---|---|---|
| a. 每列固定高度格 `s[c,k]`，有沙占据掩码 | `N=128`，`K` 个绝对高度格；能表示底湿顶干、列差与水量差。首版只做代数更新，不解渗流 | 原格上加孔隙容量、水量与格间通量；状态寻址和消费者不变 | **选用**。K=8/16 仅为性能探索档，非冻结分辨率 |
| b. 单个全局湿度+高度插值 | 数值很便宜，但没有可持久演化的局部状态 | 必须重建每列每高度状态、快照和接口 | 不选为结构；全局水量仅作为 a 的输入 |
| c. 只存经验式 `s=g(深度,水量)` | 首版可算，但没有局部扰动/湿斑的地址 | 渗透需新增整套状态并改所有调用点 | 不选为唯一表示；允许它作为 a 首版的**初始化/刷新算子** |

固定绝对高度格 `k∈[0,K)`，`z_k=(k+1/2)H/K`、`H=capacity`；沙占据 `m[c,k]=clip((S_c-kH/K)/(H/K),0,1)`，仅 `m>0` 格的 `s[c,k]∈[0,1]` 有效。用绝对高度而非“离当前沙顶百分比”使高级版的上下、相邻列通量有稳定地址；沙顶变化时更新占据掩码，空格湿度不参与力学。`s` 先注册为独立逐格状态/快照字段，而不是渲染颜色或 `WaterSandParams` 中的唯一全局标量。所需 Float32 主场约 `128×8×4=4096` B（K=16 为 8192 B），另有掩码/阈值缓存；ArkTS 帧时仍须真机测，不能拿字节数证明“免费”。

**首版语义必须诚实**：`s` 是随当前真实总水量和高度刷新、供本构映射使用的**有效湿度代理**，不是已守恒的孔隙水质量。现有 `waterTop−S−suspH−suspL` 仍是唯一物理水账；首版不把 `s·m` 再加到 `initialWater`，不从 free-water 扣一份隐形孔隙水，也不宣称含局部压力/渗透速度。高级版会在同一 `c,k` 地址加入 `P_pore[c,k]` 与 `W_pore[c,k]`，定义真正的 `s=W_pore/P_pore` 并版本化迁移；这属于水账语义升级，须重新验证守恒和已有水面效果，不能在首版偷偷完成。

## 3. 首版湿度刷新与用户水量操作

令 `Vw` 为现有水账实际总量，`Vs=Σ(S+suspH+suspL)` 为**全相沙**等效量，`q=Vw/max(Vw+Vs,ε)` 为**全局水量驱动量**；其归一化不是论文局部 `φ`。这样既有起沙/落沙与列间搬运本身不会在水量不变时假造 `q` 变化。首版选择形状明确、参数待定标的剖面族：

```text
s_eq(c,k;q) = clamp(s_base(q) + β(q)·(1-z_k/H), 0, 1),  m[c,k]>0
s(c,k)    = (1-μ_shake)·s_eq(c,k;q) + μ_shake·s_mean(q)
s_mean(q) = Σ m[c,k] s_eq(c,k;q) / Σ m[c,k]       // 只算有沙格
```

`s_base(q)` 非降、`β(q)≥0`，并额外要求对任意有效高度 `z`，`s_base(q)+β(q)(1-z/H)` 随 `q` 非降；否则“加水反使某层变干”会违反首版效果定义。高水量可使有效格趋向高饱和，低水量产生“下湿上干”。`μ_shake∈[0,1]` 是摇晃搅拌代理，在摇晃时趋大、停止后按待定标时间常数回落；它只**重排有效湿度剖面的读数**，不产生水量或声称水在孔隙中流动。`s_mean` 的体积权重使搅匀前后该代理的占据格平均值相同；因为首版 `s` 不是质量，不能将此叫水质量守恒证明。`s_base/β/μ_shake/K` 均为**候选、待效果与性能定标**，不得给论文数值作背书。若场景无沙，`s_mean=0` 且全部 `s` 无效。

用户面板建议只暴露“加水/排水”的**实际水量**控制（输入为目标量或一次增量，需按当前容量拒绝不可提交量），物理事务交现有水源/水账方案细化；不能把 `q` 滑杆直接改成水量而不入账。源码目前 `inject(WATER)` 会更改 `waterTop` 并重设 initial totals，属于离散场景/注入入口；尚无产品加/排水控件和连续排水事务。本设计不指定复用它处理实时排水，architect 须给独立事务、来源/去向、上限与 baseline 更新规则。每次已准入水操作完成后读真实 `Vw` 并刷新 `s`；拒绝操作不得改变 `s`。正常 `waterLevel` 在封闭系统中只重新分布水、`Vw` 不变，首版剖面不因其左右搬运形成局部湿斑——这是故意的保底限制，也是高级渗透要补的能力。沙顶变化导致 `m` 改变时同一算子在下一子步重算占据格；不保存旧湿斑，不进行水相局部输运。

建议在完整子步边界执行：`water command commit → read Vw/S/shake → refresh s/m → derive edge pairs → freeze moistureRevision → tilt planning/preview/apply`。一轮 preview/apply 只读同一 `moistureRevision`；若水/沙在本子步改变，下一子步再刷新，不能让 shadow 与 apply 分别读到两套阈值。`run/reset` 重建剖面并清旧湿度修订；TEST/EXPERIENCE 切换保留合法材料/水场，清路线私有缓存；方向翻转重算 donor/阈值作用边；参数编辑在安全子步边界原子提交。每次刷新记录 `q、s` 的 min/mean/max、各段格数、阈值 min/max、来源与 revision；自动化可复现同一水量/初态/seed。

## 4. 湿度 → 双角 → 五通道的**项目映射**

一条有向边 `e` 的滑移读取当前可移动**供体表层**所覆盖格的占据权重平均 `s_e`；active 方向反转后按新供体重算，不能用整列均值盖住干表层，也不能因为深处湿就直接让重沙穿过上覆轻沙。对相同绝对高度建立默认剖面 `s_ref(k)=s_eq(k;q_ref)`；`q_ref` 是冻结旧场景的默认水量身份。定义 `C(s)` 为 §1 同型分段内聚代理，`B(s)` 为高湿浮力/润滑的**独立、单调项目代理**（原文没有 `B(s)` 公式）；以 `Cmax>0` 归一化：

```text
rawΔ_e = aC·[C(s_e)-C(s_ref,e)]/Cmax - aB·[B(s_e)-B(s_ref,e)]
Δ_e    = clip(rawΔ_e, bottomCreepDeadZone+ε-20°, +4°)
θstart,e = 26° + Δ_e
θstop,e  = 20° + Δ_e          // 首版固定 6° 滞回宽度，待重新标定
```

`aC,aB≥0`、`ε>0`、`C/B` 分段点、`q_ref` 都是**待定标候选**；`B` 在全饱和端可以让净角度低于干态，但效果需实际验证。固定宽度使 `θstop,e>bottomCreepDeadZone≥0`、`θstart,e−θstop,e=6°`、`θstart,e≤30°`，不改变不可编辑 `tan30` 硬门槛。若现有 `bottomCreepDeadZone` 使可行区间为空，**拒绝配置**，不在运行时悄悄交换/扩张角度。+4° 上限意味着湿沙的真实安息角若物理上高于 30°，现有安全域无法表达，只能登记模型能力边界，不能提高 guard。现有 `thetaStart/thetaStop=26/20` 与用户配置可以作为基对，把上式 `26/20` 换成明确配置 pair；允许的正负 Δ 区间需由 `0≤stop<start≤30` 与 deadzone 重算，默认兼容证明专指 factory 26/20。

**适用范围精确说明**：当前 `P011RelaxHysteresis` 是一对**全局**斜率；S3 需要按边的 slopeStart/Stop 和版本化 active 状态，不能每子步调用 `configure()` 重置状态机。每边 `r_e`、activeBefore、供体湿度、thresholdUsed 与请求仍按原三态判据执行；湿度更新致阈值越过当前 `r_e` 时，记 `WETNESS_THRESHOLD_CROSSED` 并与倾斜转折分开，不混进旧观测③标定样本。`relaxAngle` 是首版**直接**受湿度影响的材料通道；`creepBottom` 仍用自身 deadzone 与原请求律，但其可用相位/形状/共享预算可能被 relax 改变。`settleSandV2`、`percolateHeavyConservative`、`liftByShake` 的沉降/分选/摇晃率不因阈值自动改变；第五通道及水面/悬沙扩散仅受材料和预算的间接影响。若要让这几条直接按湿度改变速率，须逐通道另出定标与安全设计，不能把“湿度影响五通道”写成已实现事实。

planner 用当前冻结的局部阈值集预演当前角度下的请求，仍只由自身动态可行域决定 `θ_eff`；§19.5 每个实际改写 `S` 的 writer 仍逐笔检查所有受影响边 `|S[c+1]−S[c]−tanθ_eff|≤tan30` 或既有违规态 non-worsening 规则。湿度只能改变**请求/调度**，不能改变 hard guard 的常数、local/bottom/total 额度、守恒/库存/容量边界；准入前后 `s` 本身不直接移动沙。湿度与大角度倾斜同时变化时先报 `source/threshold/planner/guard/budget` 各级原因，防止把 guard 拒绝误报为“湿沙不流”。

**默认兼容条款**：当 `moistureRoute=OFF`，旧场景走原全局 pair、原运算顺序和旧遥测，要求逐步位精确。`moistureRoute=ON` 且 `q=q_ref`、无摇晃剖面扰动时，`s_e=s_ref,e` ⇒ `Δ_e=0` ⇒ 每边仍 26°/20°；必须做同初态全轨迹等价验证，不能仅比参数字段。旧 26/20 锚点适用域明确缩至 **OFF 或 ON/default-reference**，不同水量/局部渗透场景不借旧锚点判 PASS；旧冻结阈值、量表和标定 BLOCKED 结论不修改。`thresholdSource` 对湿度路线登记 `factory/user base + moisture-model-version`，`thetaStartEstimate/thetaStopEstimate/CI` 仍 null，不能把逐格映射叫作已完成标定。

## 5. 效果锚点候选、验证与能力边界

固定材料量、初态、输入曲线、种子和 renderer，按**真实已准入总水量**选干/中湿/高湿三档（档位与数值采前冻结）；同一档分上/下高度格，另做 shake OFF/ON。±15° 稳定段、±45° 渐进段、翻转与长期停驻分别测；所有数值区间均**候选，待基线与目标视频同尺度定标**。

| 候选锚点 | 提取口径与预期 | 限制 |
|---|---|---|
| 垂直剖面 | occupied bins 的 `s_bottom−s_top`、高度相关系数；加水使体积加权 mean(s) 上升，摇晃使剖面差暂时缩小 | 不能拿颜色分层代替；首版局部水位变化不导致湿斑传播 |
| 起停角响应 | 每边 `θstart,e/θstop,e` 分布及真实 start/stop 转换残差，水量档间差与 CI；默认档逐步复现 26/20 | 判 `thresholdUsed`，不拿计划角；新的湿度模型需要新的候选标定协议，不能复用旧 34run 结论作完成证据 |
| 安息角/收敛 | 相同 accepted tilt 下表面残差、停止坡度、t50/t90、低/中/高水档可分辨；低湿内聚增强、高湿衰退的**非单调候选** | tan30 硬上限始终零违规；响应被 guard/预算截断时不能声称 f(s) 已验证 |
| “成团”观感 | 连续沙块轮廓长度、碎散连通域数、停驻后块体保形时间；effector 同输入盲配比较 | **阈值移动只给起停滞回，不提供真正的拉伸/弹塑性内力**。若需要沙堡式保形，首版可记录差距但不能宣称已实现，另立内聚力/应力状态方案 |
| 安全/性能 | 每步 H/L/水量守恒、库存、容量、127 边 tan30、四层预算；128×K 更新与每边查询的帧时 OFF/ON 配对 | 任一硬门槛 FAIL 不以湿度主观收益覆盖；K 与刷新频率由真机数据定档 |

验收建议先冻结“默认等价 + 安全 + 剖面与三水量档可分辨”三项，再由 effector/manager 决定需要多大的角度/观感效应量；不提前写成“必然达到 2px/30°±2°/5.1s”。若 `C(s)` 被上限截平，须报告可辨识域和被截比例；不得放宽 tan30 求非单调曲线。首版不足以表现局部渗漏/坝体破坏，保留为高级版明确目标而非验收豁免。

### 5.1 湿度路线的重新标定协议入口

旧观测③只针对**单一常数 pair**；S3 的估计对象改为 `g(z,q)`、`C/B` 形状及角度增益，因此不能把 34run 四 cell 协议直接改个字段就声称足够。建议新协议先冻结三轴输入矩阵：①真实水量 `q` 至少覆盖低/中/高并包括 `q_ref`；②同 `q` 下准备不同沙层高度，使供体表层落到不同 `z_k`，否则 `β(q)` 与全局 `s_base(q)` 不可分；③正负倾角与上/下行 ramp 分开。每个矩阵 cell 先做可达性影子审计，记录 planner accepted 角、guard 截断、真实 start/stop 及 source 格身份；采样数、fit/holdout、CI 宽度和效果阈值由 tester/manager 采前冻结，**不降旧安全门槛**。shake 档单独实验，不与静止档合并估计。

仅从起停角观测不能同时唯一识别“绝对湿度刻度 `s`、内聚幅值 `Cmax`、角度系数 `aC`”：它们存在缩放等价。首版应固定一个**模型规范化约定**（例如 `Cmax=1` 且 `s(q_ref,z)` 锚定为零修正），报告的是 `q,z→角度` 的**有效响应**，不要给 `s` 贴“实测孔隙饱和度”标签。高级版有实际 `W_pore/P_pore` 后，需用水量/湿润前沿独立观测打破该等价，并重新拟合分段点与增益。若不同高度/水量组合被 planner 或 tan30 上限系统性遮蔽，输出 `NOT_IDENTIFIABLE`，不填默认标定结论。

```mermaid
flowchart LR
  A[真实水量与水面账] --> B[首版全局 q + 高度剖面刷新]
  B --> C[同一 s[c,k] 湿度场]
  C --> D[C(s), B(s) 本构映射]
  D --> E[逐边 θstart/θstop]
  E --> F[旧 planner / 五通道 / tan30 guard]
  A --> G[高级版：free↔pore 水交换]
  G --> H[W_pore/P_pore + 格间渗透通量]
  H --> C
```

高级版将首版的 `refresh s=g(z,q,shake)` 替换为**守恒有限体积更新**：每格注册孔隙容量 `P_c,k≥0` 与孔隙水 `0≤W_c,k≤P_c,k`，`s=W/P`（`P=0` 格无效），按上下格重力排水通量与反向毛细通量、必要时相邻列通量、自由水↔孔隙水边界交换更新。概念式：

```text
W_next[c,k] = W[c,k] + dt·(J_in^vertical - J_out^vertical
                         + J_in^lateral - J_out^lateral + E_free→pore - E_pore→free)
Vwater_total = Vfree + ΣW_pore       // 外部加/排水时仅按真实事务增减
```

每条内部水通量两端同量异号；底边不漏出容器，边界加/排水有显式源汇；先限供体，再限受体容量和稳定步长，不能 clamp `s` 后丢水。水量统计、`waterTop`、材料移动时孔隙水随沙的携带/挤出、悬沙是否带孔隙水、free/pore 交界由高级版单独设计并做守恒证明。旧 `s[c,k]` 地址、`s_e→C/B→θstart/stop` 消费链、固定 tan30 与预算**保持接口**；`s` 的物理来源从经验代理升级为真实孔隙水分数，`C/B` 分段点、`aC/aB`、全局默认锚点和观察协议必须重新定标/版本化。不能把旧 `φ` 与新 `s` 数值相等或把旧冻结锚点自动迁移。

首版持久化状态须含 `moistureModelVersion`、`K`、水量基准 `q_ref` 与逐格 `s`；高级版载入首版场景时必须通过**显式迁移事务**从当前水账分配 `W_pore`，若水不足则拒绝或给有账的缩放回执，绝不凭 `s` 凭空生成水。正常运行中的局部渗透速度、毛细参数、侧向是否必要，以及真实湿沙成团需要的应力项，留给 `s3-local-seepage-v2` 单独推导与测试。升级完成的定义是“局部加水后湿润前沿可移动并改变当地阈值/材料响应，水总量闭合”，不是“用户可以调一根全局湿度滑杆”。

**设计裁决**：首版选 a 的逐列高度格状态，c 仅作首版刷新算子；保留 26/20 默认等价通道与全部安全闸门。高级版水渗透为产品终态，首版是风险对冲。工程交接见 [architect 任务书](task-P011-S3-moisture-architect-v1.md)。

## 7. 产品三维候选：高度场主体 + 必要区域局部体素（2026-10-23）

**用户提出的候选方向**：“只把必要的部分做成 3D 体素，可简化的部分仍用高度场”。本节记录其条件设计，不改写 §1–6 的一维保底首版结论；§6 所说“同一 `(c,k)` 地址直接升级”**只适用于一维截面版**。产品若要在前后方向也发生真实局部渗透，须先把背景从当前 `S[c]` 扩展为二维水平高度场 `S[x,y]`；否则前后 `y` 没有物理库存与边界，贴上 3D 体素也只是视觉假象。原 128 列路线可作为 `Ny=1` 的兼容/验证域，不能称已具备完整 3D 水沙仿真。

### 7.1 分辨率与所有权

```text
大范围：二维水平高度场 S[x,y]、重/轻层界面、水面及低分辨率孔隙水摘要
          ↓ 只在真实需要时激活局部砖块
小范围：3D 体素块 W_pore[x,y,z]、P_pore[x,y,z]、s=W/P 与局部水通量
          ↓ 回写水量/有效湿度摘要
大范围：高度场材料通道按本地湿度读 θstart/θstop，仍受 tan30/预算/guard
```

第一批 3D 块只**拥有孔隙水与湿度细节**；固体沙的占据由对应高度场和层界面投影而来，不能同时在体素内另算一份沙质量。高度场仍负责绝大部分 sandTop、bh、表面滑移与 S4 的界面重排。如果后续确需洞穴、悬垂、侧壁侵蚀等一列多个不连续沙段，才把该局部固体也交体素拥有；交接时从高度场库存扣除对应体积，回收时再守恒投影，**同一沙量只有一个所有者**。没有多值几何的地方不要为“3D”全域体素化。

背景高度场区域至少保存每个水平格的**粗孔隙水库存/少量竖向摘要格**，例如 `W_coarse[x,y,b]`；活动体素砖保存细格 `W_fine[x,y,z]`。砖块激活时从粗格守恒细分：`Σfine W=coarse W`、每格 `0≤W≤P`；回收时守恒聚合并尽量保持竖向一阶矩，避免湿润前沿瞬间跳位。活跃块互不重叠；粗格覆盖的孔隙水在块活跃期间不再重复计入粗账。块边界采用同一笔通量 `J` 两端反号记账；若邻区未激活，写入它的粗孔隙水账，而非丢弃/复制水。自由水↔孔隙水的交换仍需显式扣加：

```text
Vwater_total = Σ W_free[x,y] + Σ W_coarse[inactive] + Σ W_fine[active]
ΔW_free = −Σ J_free→pore；ΔW_pore = +Σ J_free→pore
```

体素启用的**候选触发**是局部加水/排水源、上下或侧向湿度梯度大到粗格不能表示、湿润前沿/砂坝渗漏正在移动，或出现高度场无法表达的多值几何；关闭需通量与梯度回落并完成守恒聚合。触发/关闭阈值、砖尺寸及缓冲圈都待误差与真机成本定标，不能凭摄像机近远或视觉亮度决定物理所有权。失配时保持粗解并报 `LOCAL_3D_RESOLUTION_INSUFFICIENT`，不在无账状态下静默新建湿沙。

### 7.2 计算成本与验证门

成本按**活动体素数**而非整个容器体积估算：`memory≈NactiveVoxel×Nfield×bytesPerField×(live+snapshot+scratch 系数)`，步进成本为活动体素/通量面数加粗细边界交换。仅作量级例：一个 `16³` 砖、6 个 Float32 字段的 live 数组约 `16³×6×4=96 KiB`；32 块约 `3 MiB` live，快照/临时缓冲另计。全域 `128³`、同样 6 字段约 `48 MiB` live，且每步处理约 209 万体素。上述 K/砖数/字段数均**非冻结方案**，不能把内存估算当成帧时证明。

分级验证顺序：①现有 1D 列+纵向属性格保底版；②`S[x,y]` 的二维水平高度场与旧 `Ny=1` 截面等价/守恒；③单块静态水账与粗细投影恒等式；④多块移动湿润前沿、块生灭和上下/侧向通量闭合；⑤湿度→局部双角→材料形变及真实设备帧时。每级独立记录版本/routeId，不拿 1D 26/20 冻结锚点判 3D 路线 PASS。S4 对 `bh` 的缓慢形变仍先由高度场承担；方案 3 的悬沙平流仍是不同库存通道，二者不会因“局部体素”自动获得免费质量或额外 300/s 额度。

**候选条件结论**：若选择局部体素路线，三维基底须是“二维水平高度场主体 + 按需局部 3D 孔隙水体素”，真实多值沙体几何仅在出现明确效果需求时另批局部固体体素。首版一维湿度剖面是风险对冲与状态接口验证，不冒称已经完成产品三维化或局部渗透。

## 8. 对用户三维建议的设计复议：分层高度场优先，局部自由体素候选（2026-10-23）

**语义更正**：用户明确说明 §7 的混合体素路线只是建议，**并未裁决为产品架构**；先前稿曾误标为“用户裁决”，现已更正为候选路线的条件设计，不是经理已批准的实现前置。此节给 designer 的当前推荐；最终路线仍由 manager/用户按效果和成本证据决定，保留 §7 作为候选知识资产。

| 路线 | 能表达的对象 | 新增关键复杂度 | 当前建议 |
|---|---|---|---|
| **分层高度场**：沙体/自由水仍用高度场，柱内有限个孔隙水层 | 下湿上干、重力排水、毛细回润、横向湿润前沿；在现有画布先用 `x,z`，将来真三维视角用 `x,y,z` 的**列对齐标量格** | 水量和孔隙容量账、层间/邻列守恒通量；无活动砖块生灭或固体所有权切换 | **首选**。`W_pore`/`P_pore` 是每列竖向层，不是把全部沙粒变成 3D 体素 |
| §7 局部自由体素 + 高度场 | 上述现象之外，可局部处理高度场无法表示的多值固体几何与真实三维水流细节 | 粗细界面通量、砖块激活/回收、双模型同步与唯一库存、帧时尖峰 | **条件候选**；先用目标场景证明分层高度场有可测缺陷，再只对失败区域升级 |
| 全域固液 3D 体素 | 任意孔洞、悬垂、绕流和沙体破裂 | 全域多相状态与求解成本、手机性能和旧账本迁移 | 不作为当前产品路线 |

推荐路径的地址演进为 `S[x] + W[x,k]`（现有手机截面）→ 若需要前后方向，`S[x,y] + W[x,y,k]`。后者数组在数学上有三个索引，但**只有孔隙水湿度是竖向分层**；沙体表面仍是一张单值高度图，底层/重轻层仍是少数界面，不承担自由 3D 固体求解。`k` 可先固定 K=8/16 作误差/帧时比较，再考虑局部增加层数；不要同时引入变 K、二维基底迁移和活动体素块。真实渗透的有限体积交换可先沿相邻 `k` 与相邻水平格记同量异号通量，满足 `Vwater=Vfree+ΣW_pore`；旧 S3 首版 `s=g(z,q)` 仍仅是风险保底，不拿经验湿度冒充这条守恒路线。

**何时升级 §7**：目标视频/交互确实出现一列多个不连通沙段、悬垂/洞穴、绕立体障碍的水流，或分层模型在已冻结场景上持续无法匹配**局部湿润前沿的位置/速度**，且提高 K/横向分辨率后仍不能纠正。前两类是高度场的表示极限；后一类需先排除错误水力参数/边界，再判断是否必须 3D。仅因为画面要 3D 镜头、湿沙表面要立体光照，**不足以证明需要固液自由体素**。若局部体素立项，§7 的粗细守恒与唯一所有权仍是硬条件。

外部依据仅支持路线形态，**不是手机性能承诺**：[Su 等 2023](https://kuiwuchn.github.io/RTWaterAndSand.pdf) 用高度场处理沙水并明确其竖向变化/尖锐结构限制；[Garres-Díaz 等 2020](https://arxiv.org/abs/2001.04672) 说明少量竖向层可恢复被单层平均抹掉的变化；[Chentanez 等 2014](https://matthias-research.github.io/pages/publications/hybridsim_preprinted.pdf) 证明大范围高度场与局部 3D 流体耦合在图形学上可行，但研究对象是大型液体、实现平台是桌面 GPU，不能直接推出 P-011 孔隙水/沙体在 ArkTS 真机上的成本或正确性。本项目先用最小分层模型产出质量守恒、湿润前沿和帧时证据，再决定局部体素是否有必要。

## 9. 摇晃起沙的干、潮湿、水下三工况修订（2026-10-23，设计增补）

**需求与现状。** 用户要求摇晃时干沙、潮湿沙、被水淹没的沙呈现不同效果。现有 `liftByShake` 只从顶部沙库存扣量并写入同一列 `suspH/suspL`；它既不检查自由水是否存在，也不记录在途沙的纵向位置或空气/水介质身份。无自由水时，`capacity = waterTop−sandTop+desired−suspH−suspL` 仍可能准入 `desired`，因此当前实现可把干沙写入名义上的悬沙库存。§4 的“lift 不直接随湿度变”准确描述原首版范围，但**不足以覆盖本节的新产品效果目标**。本节是后续摇晃路线的算法输入，状态为 `DESIGN_ADDED / ARCH_REVIEW_REQUIRED / NOT_IMPLEMENTED`；原 S3 仅双角版本不能宣称三工况效果已完成。

### 9.1 分类输入必须分开

每列在子步开始冻结两个量：表层有效格的局部饱和度 `s_surface[c]`，以及真正可用的自由水厚度 `h_free[c]=max(0,waterTop[c]−sandTop[c]−suspH[c]−suspL[c])`。前者决定干/潮湿材料黏聚趋势，后者决定起沙后进入空气还是水。`h_free` 必须读材料水账，不能从全局加水量 `q` 或白色雾像素推断；介质切换采用采前定标的进入/退出滞回，以免零附近每子步跳档。`s_surface` 在 S3 首版仍是 `g(z,q,shake)` **代理值**，只能验证设计接口和候选效果；真实局部湿斑及水桥强度需高级版 `W_pore/P_pore` 与试验校准，不把代理值写成已测局部含水率。

| 工况 | 判定输入（阈值均为待定标候选） | 起沙后物理身份 | 可见效果与明确边界 |
|---|---|---|---|
| 干沙、无自由水 | `h_free≈0` 且 `s_surface` 低 | 空气在途重/轻沙 `airH/airL`，按有限在途批次记录高度和速度 | 少量颗粒短跃、快速落回；不能画成水下浑浊。只有增设在途库存后才可称“飞起来”。 |
| 潮湿但未淹没 | `h_free≈0` 且 `s_surface` 落在水桥作用段 | 空气在途**团簇** `aggH/aggL`，每团有质量、质心和状态；破团须守恒转移到空气细粒或沉积 | 更高起动门槛、更少起沙，出现较大团簇短程跳落；单独调 26/20 双角不能生成团簇物理。 |
| 被自由水淹没 | `h_free` 超过淹没进入阈值；饱和度另行影响残余黏聚 | 不需要逐点轨迹的细沙进入水中 `suspH/suspL`；需看见独立运动的颗粒进入有质量的 `waterParticleH/L` | 细沙形成浑浊羽流，较显眼颗粒有受阻上升/下降轨迹；方案 3 的悬沙平流只作用 `susp`，不能自动替水中颗粒求轨迹。 |

潮湿与全淹没不是同一个“湿档”：完全浸没时毛细桥效应与有效重力、流体拖曳的组合不同。依据是 [Su 等的沙水耦合模型 §3.3.3](https://kuiwuchn.github.io/RTWaterAndSand.pdf) 对饱和度分段摩擦/内聚的区分，以及 [Richefeu 等 2006](https://doi.org/10.1103/PhysRevE.73.051304) 对非饱和水桥增强剪切强度的实验；**两文都没有提供本项目的摇晃起沙率或团簇尺寸系数**。

### 9.2 请求律、准入和去向

共用实测或 TEST 输入的摇晃强度 `E[c,t]`，但三条请求律独立：`q_req,j=dt·k_j·A_exposed,j·max(0,E−Y_j)`，`j∈{dry,damp,submerged}`。`A_exposed` 是可拆出的表层库存/暴露度，不超过 donor 的真实 H/L 库存；`Y_damp(s)` 应在中湿水桥段高于同材料的干态候选，`Y_sub(s,h_free)` 另受浮力、拖曳和可用自由水空间约束。`k/Y`、团簇质量和在途速度全是**待效果定标候选**，不借用 `thetaStart/thetaStop=26/20` 充当摇晃阈值，也不把文献分段函数直接当动力学率。摇晃本身的加速度和表面坡度共同影响起沙方向/落点；若只保留现有标量 `shakeEnergy`，必须标明横向落点不可辨识。

每笔请求先按原 local/channel/total 预算与库存裁剪，再由 §19.5 guard 对 `ΔS=−q` 逐笔联合预演；仅对 `q_granted` 调用 `splitTopV2`，并**恰好写入一个目的库存**。无自由水时不得写 `suspH/suspL`；水下颗粒与水中列浓度须分账，不能把一份 `susp` 再画成另一份有质量粒子。实际落回沙床时，反向 `ΔS=+q` 仍经对应 writer 的预算和 guard；若落点被拦截，在途库存保留并报阻断，不凭空退款或渲染已经落定。通过水面时 `air↔waterParticle↔susp` 是同量同相的库存转移；团簇破碎同理，不得重复计入新沙源。跨列在途漂移若实施，须单独计入真实横向通量/一阶矩，不能借水下 advection 免费搬运。

对每相 `p∈{H,L}`，扩展后的守恒身份为 `V_p=V_dep,p+V_susp,p+V_air,p+V_agg,p+V_waterParticle,p`；外部掉沙注入另按已准入 `I_p` 加到期望总量。团簇由 H/L 双相质量组成，不把水桥的水量当沙量；未来高级版水桥含水由 `V_free+ΣW_pore` 单独核算。snapshot/checker/重置/routeId 必须包含新增在途身份，直到架构与测试补齐前不能将其加入现有冻结验收路线。

### 9.3 表现、路线选择与验收候选

对产品目标，推荐复用[纵向掉沙路线 C 的“真实颗粒 + 高度场”混合身份](design-P011-falling-sand-vertical-routes-v1.md)，但只把**已脱离沙床、需要可见独立运动的少量质量**放入有界颗粒池；沉积大宗仍由高度场表示，不逐粒离散整床。水下未解析细沙继续用悬沙列账，产生浑浊；列内有限批次（路线 A）可先做成本较低的物理原型，但单一批次高度不能冒充独立颗粒轨迹。路线 B 只能作明确标记的视觉预览，不满足“每个可见运动体有物理质量”的目标。同一渲染 adapter 只读已准入颗粒与悬沙，画颗粒轨迹/团簇和水下浑浊。S3 首版的双角/剖面代理仍可单独交付，但**不得以此通过摇晃三工况的效果验收**。既有 P-012 水上白雾和下层颗粒锚点仍照旧；水下浑浊只在已准入悬沙处叠加，空气飞粒不得被白雾误认。

效果对照固定相同摇晃输入、表层 H/L 可用库存、初始坡形和渲染档，分别准备干、潮湿、淹没三态，并另做无沙/无自由水/摇晃为零反例。采前冻结候选量：`liftGranted/E`、空气在途峰值和停留时间、团簇数与质量分布、淹没水柱的悬沙峰值/沉降半衰时间、三个工况的可辨识主观评分；干态水下悬沙为零，水下干尘为零。所有质量、容量、预算、tan30 guard、跨介质转移与 FPS 为硬核验；数值效果阈值待 effector/tester 同真机素材定标，**此处未冻结新锚点或修改旧锚点**。若架构仍只保留一份 `susp`，报告 `SHAKE_MEDIUM_IDENTITY_MISSING`，不得宣称三工况达标。

### 9.4 高度场与有限颗粒层的所有权边界（用户追问，2026-10-23）

高度场只表示每列已沉积沙床 `S[c]` 及其重轻层，不能存脱床颗粒的高度、速度、路径、相互分离或再次撞床。当前 `suspH/L[c]` 也只有列总量，没有纵向坐标，所以它可作为水中未解析细沙的浓度/质量近似，不能独立预测可见颗粒轨迹。需要看到颗粒飞起时，使用稀疏活动层 `P_i=(id,phase,mass,x,z,vx,vz,medium,source)`；这是二维截面中的真实质量包，**不等于把整层沙体体素化，也不保证一包恰好是一颗天然沙粒**。仅当一组沙离开床面时从高度场扣出 `q` 并生成粒子包；休眠沙始终留在高度场。

物理子步顺序候选：`摇晃输入→逐笔 lift 准入→床面 q 转粒子/水中细沙→推进活动粒子→水面跨介质→与高度场碰撞→逐笔 settle 准入→审计`。干粒在空气中受重力/碰撞而短跃；潮湿包可带团簇质量与后续破团事件，若要真实预测团簇尺寸还需独立黏聚/断裂律；水中可见颗粒受重力减浮力、拖曳和流场作用，未解析细沙留在 `susp` 扩散/平流。现有物理场没有逐点水流速度或粒径身份，故首批只能给**待定标的低阶漂移/阻尼近似**，不能称为完整流固粒子仿真。`heavy/light` 是相身份，未经材料定义确认，不等于 `coarse/fine`；可见颗粒与列浓度的分配须另设材料粒径或视觉解析阈值并校准。

每个可见物理包只由一种库存拥有：`deposited→air/aggregate/waterParticle/susp→deposited`，每次转移 H/L 两相逐笔对账；床面移出和撞床写入仍守 local/channel/total 预算及 §19.5 guard，跨列物质移动真实扣费。颗粒数封顶、按同相近位置/速度合并成保质量与一阶矩的批次，满额后拒绝新 lift 或按明确身份转为水中列浓度；干态**不能**静默退化进水中 `susp`。有界粒子层每子步成本约 `O(N_active+128)` 加碰撞/绘制，粒子上限与 FPS 须真机定标；只渲染物理包的一部分时是抽样显示，不可据屏幕点数反算总质量。必须补 snapshot/checker、粒子接触阻断队列及 reset/invert/TEST/EXPERIENCE 生命周期后，才能进入实现评审。
