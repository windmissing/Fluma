## 4. 正式采集字段清单（反馈 effector，避免再废一批）

分析脚本 + 本批次教训推导，**正式采集 want/文件命名字段要求**：

### 4.1 want 参数（每臂必传，OFF/ON 双臂都要核对）

| 字段 | 取值 | 作用 | 漏传后果（本批次实证） |
|---|---|---|---|
| `p012tier` | `3` | C 层理总开关的层级门 | **本批次废批根因**：漏传 → 两臂均 canonical，ON 臂层理从未渲染 |
| `p012ablate` | ON 臂不传；OFF 臂 `strat` | 仅关 C 层理（主比较 B 开启） | 漏传 → OFF 臂也开层理，两臂无差异 |
| `rendermode` | `4` | waterand 场景 | 已验证必传 |
| `wspreset` | `thick` | 固定水位/沙量预设 | 两臂必须一致 |
| `p012seed` | 固定值（如 `20261016`） | 确定性渲染 | **注意参数名是 `p012seed` 不是 `seed`**（写 `seed` 会被静默忽略，历史教训） |
| `testmode` | `true` | 传感器不接管，重力全由手势构造 | 漏传 → 采集被真实传感器污染 |
| `wssnapshot` / `forceinvert` | `false` / `false` | 排除快照/倒立干扰 | 两臂一致 |

### 4.2 文件/目录命名与标注（分析脚本消费约定）

| 项 | 约定 | 原因 |
|---|---|---|
| 目录名 | `pair{n}-{off\|on}`（n=1,2,3…） | 脚本按此枚举 |
| 帧名 | `pair{n}-{mode}-{phase}-{k}.jpeg`，phase ∈ {static, tilt, return} | 脚本按文件名分相位；return 目前被丢弃（P-3），命名保留以便修复后回补 |
| **tier 标注** | 批次目录放 `collect-manifest.json`：至少含 `{"p012tier":3,"p012ablate":…,"p012seed":…,"build":"entry-default-sN-signed.hap","sha256":…,"timestamp":…}` | **本批次废弃的直接教训**——无 tier 标注 = 无法自证 ON 臂真的开了层理。P-6 修复后分析脚本将消费此清单写进输出 provenance |
| 帧数 | 每对每臂 static×3 + tilt×2 + return×2 = 7 帧 | 与已验证批次一致；static×3 用于静止零漂移检查 |
| 分辨率 | 保持 1280×2832（BOX 归一化按 516×1080 换算） | 换分辨率需同步核对 BOX 边界 |

### 4.3 采集后自检（30 秒，强烈建议入 SOP）

1. 抽 1 对 static-0 做 OFF vs ON 像素差分：**npx>3 应显著 >0**（有效批次 ~74.6 万 px）。若 =0 → 两臂同渲染，立即停，检查 `p012tier` 是否真传入（等价于把 P-5 哨兵前移到采集端）。
2. hilog 抓 `strat: bitmaps H=ok L=ok M=ok`（三张位图烘焙成功）——ON 臂特有，OFF 臂无此行。
