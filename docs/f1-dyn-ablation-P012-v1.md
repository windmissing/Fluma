# P-012 F1 消融实测：静态/动态层占比（v1）

任务：6ad9aae7e4b0ae0eea66417d（F1 消融——离屏预合成收益关键数据）。
前置：f1-offscreen-model-validation-v1.md（估算模型精度验证，静态占比被列为
最大未知数）；本报告以实测补齐该分量，并修正离屏预合成收益估算。

## 0. 摘要

- **静态层成本实测 ≈ 1ms**（严格冷态配对，off render p50 8ms vs dyn 7ms，
  n=97/77）——占渲染预算 **12%**，远低于估算模型假定的主体份额。
- **离屏预合成收益上限修正为 ≤1-2ms**（原估算 5-11ms），不足以单独支撑
  90Hz 单拍（11.1ms）目标。
- 90Hz 满帧的真瓶颈移向：**物理子步（轻载 12ms）+ 动态层渲染（7ms）**。
- 附带产出：E3 I2 真机性能修复（发现并修复 52 倍帧时退化）与设备热态
  降频方法论（详见 §3/§4）。

## 2. 实测数据（s132，严格冷态配对）

### 2.1 采集与热态干扰

设备 VYG-AL00 连续采集下 **thermal_zone0 达 60°C 临界 → CPU 限频至
418-558MHz**（正常 ~2GHz 级）。降频使绝对帧时失真（p50 106-127ms），
但 **physicsTime 哨兵可识别热态**（正常频率轻载物理 p50≈12ms，热态 45ms+）。

配对有效性判据（严格冷态窗口）：
- `physicsTimeMs ≤ 15`（频率正常哨兵）
- `frameTimeMs < 45`（节拍域内）
- `substeps > 0`（动态帧）

### 2.2 核心结果

| 指标 | off（全量） | dyn（只动态层） | 差 |
|---|---|---|---|
| 冷态动态帧 n | 97/291 | 77/273 | — |
| render+other p50 | **8 ms** | **7 ms** | **1 ms** |
| frameTime p50 | 19 ms | 16 ms | 3 ms |

physics 哨兵两块一致（12/11ms）→ 频率状态对齐，配对有效。

### 2.3 与 F1 归因报告（s106）的口径差异

s106 归因报告的「render+other p50 15ms」是 **E3 之前**的构建：
- 旧 12 档雾（fillFogTiers 逐列采样 + rgba fill）
- CanvasPattern 光栅路径尚未全部 drawImage 化

s132（E3 雾 buffer 化 + C 层理 1px 列拉伸后）：**冷态渲染已降到 8ms**。
即 E3/B/C 三轮优化已把渲染成本砍掉约一半——F1 归因的 15ms 基线已过时，
后续 PERF 判定应以 8ms 为新基线。

## 3. 离屏预合成收益修正（对接 f1-offscreen-model-validation §2）

| 分量 | 原估算（s106 基线） | 实测/修正（s132 基线） |
|---|---|---|
| 静态层可缓存部分 | 未知（假定为主体，上限 ~7ms） | **1ms（12%）** |
| 动态层必须重绘 | 5-9ms（推算） | **7ms** |
| 离屏预合成总收益 | 5-11ms（低-中置信度） | **≤1-2ms** |

**结论**：离屏预合成对当前构建收益有限（≤2ms）。90Hz 单拍（11.1ms）
的达标路径上，静态层已不构成障碍；剩余障碍：
1. 物理轻载 12ms（子步管线，属 P-011 物理域）
2. 动态层渲染 7ms（沙体三带 fillRect 游程 + 界面带 + E3 动态烘焙）

给 manager 的指标裁决①补充：**选项①（指标按 90Hz 修订）的实现成本上升**
——需要物理子步优化（P-011 域）而非渲染重构。

## 4. 附带产出：E3 真机性能修复（重要）

### 4.1 发现：E3 I2 帧时 52 倍退化（s118-s125 排查）

F1 采集首跑发现帧率 0.6-7fps（frameTimeMs 1200-1600）。二分定位
（s119=HEAD 无 dyn / s120=f91486e / s121=a46fcb5 / e3i2-e3n1 消融对照）+
分段计时诊断（s123/s128/s129/s130）锁定三个叠加因素：

| 因素 | 真机成本 | 修复 |
|---|---|---|
| transferBitmap 每帧调用（帧循环内 OffscreenCanvas putImageData+transfer） | ~600ms/帧 | 移除调用（降级上屏不读位图） |
| N1 场 shiftAndBake 每帧全窗口重算（bakedPx=1，121k 格点） | ~436ms/帧 | bakedPx=2（4 倍减量）+ 同窗口短路跳过 |
| fogPhaseX() 在烘焙内层逐像素调用（内含 128 列求和 → 62 万次浮点加法/帧） | 主要剩余 | phaseX 提出循环（每烘焙 1 次） |
| 层高增量阈值 1e-9（沉降中每帧必 dirty） | 每帧重烘 | LAYER_EPS=0.25 物理格 + q 阈 0.01 |

修复后（s127+）：E3 全链（失效检测+烘焙+shift+tiers）**0-1ms/帧**
（真机 RDIAG 实测）；渲染全链 3-5ms。

**注意**：Node 单测对上述全部不敏感（JIT 内联 + 快 50 倍的 TypedArray），
真机 ArkTS 解释开销使方法调用密集循环的成本放大两个数量级——**E3 类
像素循环代码必须真机验证帧时**，Node 单测只保正确性。

### 4.2 设备热态降频（采集方法论）

- thermal_zone0 60°C 临界 → CPU 418-558MHz（正常 1.19GHz+）→ 全部
  时间测量值膨胀 3-5 倍
- 识别方法：`physicsTime` 哨兵（正常 12ms / 热态 45ms+）+
  `/sys/class/thermal/thermal_zone0/temp` 直读 + top 主线程满载但低产出
- 连续采集 >1 分钟即触发；配对块间必须冷却或用冷态窗口过滤
- 本报告 §2 的严格冷态过滤即为此设计

### 4.3 构建链

s118（dyn 首版，E3 退化未察觉）→ s119-s121（二分定位）→ s122（删
transferBitmap）→ s123（分段诊断：bakeW 424/shift 436ms 铁证）→
s124（64 宽无效——瓶颈不在循环量）→ s125（bakedPx=2+短路）→
s126（LAYER_EPS）→ s127（phaseX 外提，E3 全链 0-1ms）→ s128-s130
（render/帧级分段：定位到热态）→ s131（干净版）→ **s132（dyn 恢复+
最终采集版）**。
