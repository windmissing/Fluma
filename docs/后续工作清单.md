## 当前执行约定

- 目标20常规工件核对、签包和部署收据并入 effector 真机验证卡。tester 负责独立离线验证和共用测试设施，只有独立交付价值的工作才另建卡。
- 目标20以后新派问题分析与首次归因由 architect 负责，developer 按工程结论实施与编译。已分配任务的角色、范围、优先级及状态沿原安排，T732 仍由 developer 执行。
- developer 实施时，architect 并行准备下一项已具备输入的离线架构；对尚待实测的实施决策写清触发条件，不等整轮开发或真机结束才开始准备。
- 目标1–19全部暂停，当前仅目标20 Shader 编译优化执行，任务为P5。暂停包括新派工、在途执行、离线验证和真机排期。保留原状态、依赖、产物和证据，等待用户明确恢复。已经停止的投入继续停止。
- 新增目标20：Shader 编译优化。目标20任务按P5排期，首卡T727由architect负责，独立于首帧专项两角色流程。分别量测首次编译、链接、缓存命中和首个有效Swap。
- 端到端受阻时，优先拆出可独立交付的离线验证，按普通流程排 P4 或以下。离线结果和端到端结果分别登记，已经具备离线前置的任务可并行开工。
- P5 仅用于直接分析、修复或复测首个有效帧阻断，专项只设 developer（分析、修复、编译）与 effector（测试开发、签包、真机验证）。非首帧工作按 P4 或以下并行推进，沿原角色流程：designer 设计算法，architect 落工程合同和失败首归因，developer 开发编译，tester 离线准备及验证，effector 真机和观感验证。可开工的普通工作无需等首帧专项结束，真机仍串行且优先安排首帧专项。混合任务的后续功能、物理或观感验证按普通优先级调度。
- 首帧专项只设 developer 和 effector。developer 负责分析、工程决策、修复与编译交付；effector 负责测试开发、夹具、离线核对与签包，以及需要时的真机验证和采证。问题直接由 effector 反馈 developer，沿实际产物交接。专项外沿原角色流程。
- GPU驻留仿真优先，CPU停止投入；渲染仅XComponent+shader，禁止Canvas回退。
- 目标1–11不变，目标10暂停；12及以后按13→14→12→15→16→17→18→19调度。旧湿M1任务仍按阻塞表暂缓。
- developer负责开发、编译；tester负责不使用真机的用例/夹具/脚本/host测试、构建签名和离线分析；effector负责全部真机部署、客观测试与主观采证，任务须有“真机”标签，设备串行。
- 只有实质方案/开发/数据/产物前置未齐才阻塞，仅等待设备窗口放可开工。失败首次归因由architect负责。
