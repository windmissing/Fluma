# T58复盘：P051_DRY_AIR_SOURCE_V1

日期：2026-10-26。designer，不使用真机。阶段：隐藏水候选的合同冲突→干场源方案。设计已交付，未实现/未验证。

T51的隐藏水选择保留了旧湿事务的合法性，但只能证明零沙，不能满足真正无水空容器。T50表格提前写入了零水reset目标，却没有同时提供合法干场准入接口；本次把这个缺口按独立源事务补齐，旧卡不重开。

源码显示guard有多层：外层NO_WATER后还有水位η求解、底层出生Y夹水面/X抖动、SPAWN/CROSSING水域余量、HOT及field容量审计。因此只改一个if或一个Y参数必然遗漏其它边界。空气分支还固定竖直加速度；干场若继续沿用它，T50方向只影响床或显示，无法证明真实空气粒子同向受力。

| 候选 | 结论及原因 |
|---|---|
| 保留不绘制的水 | REJECTED：初始真实水库存非0，空气触点仍夹水域 |
| allowNoWater/删旧guard | REJECTED：改变湿场合同且后续低层限制仍在 |
| 页面pool.allocate或legacy inject | REJECTED：绕过原子源、count/E/发布或重设基线 |
| 物理waterTop永远0而其它逻辑完全不改 | REJECTED：原O≤waterTop与渲染top≤water校验失败 |
| 新干场引擎与单独source账本 | 后备：隔离强，但重复既有预算/事务/同帧发布成本大 |
| 显式dry模式、W=0、waterTop=O退化包络 + 独立触点事务 | 推荐：保留审计不等式与上传布局；需要严格medium身份、候选包络更新和dry容量/空气分支，不能只在发布末端补值 |

设计把新能力限定到一触点H/L原子批次、干场专用出生/空气版本、旧湿路径兼容；池满不降级为列悬沙，显式干场invert在实现前拒绝，避免藏入未设计行为。反例要求覆盖空E、精确触点、半笔失败、source重放、跨列与LAND、零水量和预演一致性。下一轮需tester冻结独立RED与T59实现证据，再由独立测试/设备效果评价；本稿不把数学合同当已运行产品。
