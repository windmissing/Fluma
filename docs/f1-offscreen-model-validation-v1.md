## 1. 「blit ≈2-4ms」的依据强度验证

### 1.1 估算出处溯源

归因报告 §3 ① 写「静态层 blit（~0.9Mpx drawImage 1 次 ≈2-4ms）」。溯源结果：**该数字继承自 architecture §10.2 F3 的「静止态退化为单次 blit（~0.29Mpx，2-4ms）」**，而 §10.2 的 2-4ms 又来自 §10.1 成本模型的 **4ns/px 假设**——该假设标定对象是 **CanvasPattern 软件光栅采样**（12fps 阻塞轮归因用的 28ms/带 量级推算），**不是 drawImage 位图块传输**。两类操作成本结构完全不同（软件逐像素采样+混合 vs GPU 位图块拷贝）。

**结论：2-4ms 无 drawImage 实测支撑，是 pattern 光栅成本向 blit 成本的错误迁移。**

### 1.2 既有数据对 drawImage 成本的间接约束

| 证据 | 数据 | 对 blit 成本的约束 |
|---|---|---|
| **C 层理配对（strat-s106）** | 12 次 drawImage（源 1px 列拉伸）+9 段 clip+6 fillRect 净增量：P50 +0.00ms / P95 −1.01ms | ≤0.15ms/12 次 → **单次非 1:1 drawImage ≤0.012ms**（提交侧几乎免费） |
| **B 档消融（ablate-s104）** | grain 消融（撤 12-36 次 256² tile drawImage）vs off：33-35 vs 32-36 fps | 颗粒层全套 drawImage **<1ms 量级**（FPS 分辨率内不可辨） |
| **s99 ladder 静置 tier3** | EAB（含 B 档全量）p50 16.67ms=60Hz 单拍 | 静置时整套 EAB 提交+RS 落 16.7ms 内——**总提交侧不超时但无余量信息** |

### 1.3 修正后的 blit 成本估计

按 C 层理证据外推：全幅 0.9Mpx 1:1 blit ≈ 0.012ms×3（面积比）≈ **0.04ms 量级**，比报告估算低两个数量级。**这对估算模型是利好而非利空**——静态层 blit 比假设更便宜；但 8-11ms 估算的另一端（省下多少）同样需要修正（见 §2）。

## 2. 模型边界与置信度分级

### 2.1 render+other ≈15ms 的可分解性（现有遥测能做到的）

两独立来源交叉一致：动态轻载帧 28ms − 物理 13ms ≈ 15ms = render+other p50 15ms ✓。但**遥测无法再分**：
- **vsync 等待**：静止帧 17ms 是节拍锁定值，render+RS 真实值在 (0, 16.7] 内任意都可能
- **RS 合成**：RS 侧耗时不在应用遥测内（architecture §7 预检结论 DATA_SOURCE_UNAVAILABLE 的老问题）
- **提交 vs 光栅化**：fill/Path 的 CPU 提交与 GPU 光栅化在 WS_FRAME 口径里合并

### 2.2 离屏预合成收益的分量表（逐项置信度）

| 分量 | 数值 | 依据 | 置信度 |
|---|---|---|---|
| 现状 render+RS（动态） | ≈15ms | 双源交叉（§2.1） | **高（实测一致）** |
| 其中 draw 提交侧（全部 draw） | ≤1ms | 消融配对（grain/C 层理） | **高** |
| 其中 E/A 层 fill/Path 光栅+RS 合成 | ≈14ms | 15−1 的差值（**推算**——假设提交侧全部便宜） | **中** |
| 静态层 blit 成本（新） | 0.04-2ms | C 层理外推 0.04（低界，1:1 无缩放）；2-4 估算已被 §1.1 否定，但**全幅缩放 blit 无实测**——保守上界保留 2ms | **低（跨 1.7 个量级未定）** |
| 动态层保留成本（沙体三带+界面带重绘） | 5-9ms | **纯推算**：E 档游程 fillRect ~10 draw + 界面带 12 档——单 draw 光栅成本无实测 | **低** |
| RS 合成下限 | 未知 | 预合成后合成层数变化（离屏内容与主画布的合成路径）未测 | **无数据** |
| **端到端估算** | **5-11ms** | 上表合成 | **低-中（关键分量两低一无）** |

### 2.3 8-11ms 估算的修正结论

原估算 8-11ms 的两端都有分量错位：blit 端高估（2-4→0.04-2ms）、省下端（14ms 中静态层占多少）无实测——**E/A 层 fill 里「静态可缓存部分」与「动态必须重绘部分」的占比是整个估算最大的未知数**（底色/边框/雾静态斑驳约占 E/A 提交面积的几成，从未单独消融）。估算区间应放宽为 **5-11ms 且两端置信度低**；「有望 90Hz 单拍」的结论**方向成立但数字不可用于决策承诺**。

## 4. 结论摘要

1. **「blit≈2-4ms」无实测支撑**——溯源为 pattern 光栅成本假设的错误迁移（§1.1）；修正后 blit 可能便宜两个量级（对方案有利）
2. **15ms 基线可信（双源交叉）**，但其内部分解（静态可缓存占比）无实测——这是估算的最大未知数，不是 blit 成本
3. **8-11ms 估算修正为 5-11ms、低-中置信度**——方向（预合成能显著降低 render+RS）有消融证据间接支持（提交侧便宜+光栅是主体），数字不可作承诺
4. **第一批实测建议**：静态/动态占比消融（最便宜、决定性）→ blit 实测（注意平台坑绕道）→ RS 增量（工具风险）→ 端到端
5. 与 E3 的交叉：I2 上屏通道修复（putImageData 平台坑）与实测②是同一件事——建议合并排期
