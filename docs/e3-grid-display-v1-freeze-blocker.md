## 1. 当前硬阻断与数值账

按复测纯雾带设备 ROI rows 945–1160，OFF `pxStd=13.71`、ON `pxStd=9.38`，比值 `9.38/13.71=0.6842`，低于已预注册的防抹平候选警戒带 `[0.90,1.10]`。同一 OFF 下，ON 至少需 `0.90×13.71=12.339`；现有缺口 `2.959` 灰度 std，即 ON 需比现值增加约 `31.55%`。这是候选保护项的违反，不能通过改低下限求绿。

复测报告追算 s117 同语义 ROI 为 ON `12.44`、OFF `13.71`、比例 `0.907`；s132 ON 比 s117 低 `3.06`（约24.6%），但该追算值尚须归档原帧路径、脚本版本和同一 ROI/methodId 的可重算输出，才可作为跨构建因果证据。s117 原始 920–1160 ROI 混入空气黑带，报告中的0.999不能与s132的0.684直接比较。

s132 `e3n1` 臂（I2保留、N1回退旧mottle）`pxStd=12.22`，比ON高 `2.84`，达到 `12.22/13.71≈0.891`，仍略低于0.90。这个对照提示**N1路径或其缓存可能贡献大部分缺口**，但 `e3n1` 同时改变噪声分布与可能的失效路径，不能单凭一张静态图裁定“算法抹平”还是“dirty欠更新”。雾上限0.78也不能保证增加fog倍率后std单调上升；光学厚度饱和可能使纹理更均匀。任何大于1的 `fogDensityScale` 都只能在假设A确认后作为离线候选扫描，水雾alpha上限仍为0.78，界面上限仍为0.55。

**developer只读代码归因（本轮，尚非真机裁决）**：`9827739` 在修复52倍帧时退化时，除将 `LAYER_EPS` 从1e-9改为0.25，也把 `P012_E3_BUFFER_W` **256→64**、N1 bakedPx设为2并增加短路。降级上屏仍用 `segU=8/segV=8`；水平雾带分段由32组变8组，缓冲高度等比缩小时垂直组数也约降4倍。宽度缩小属于**A：I2算法/采样面变化**，不能把“修复只改帧时、不改算法面”继续当成已经证实的事实。设计稿I2主档原为256，64属需说明的偏离；若恢复256有帧时成本，须先做成本/收益配对，不能直接回退实现。首次创建buffer时必dirty、必烘；但采集脚本在各臂冷启动后**等25秒才截static-0**，因此现有静态截图并非首帧。沉降期间每帧无条件更新`e3PrevSmooth`/q快照，可能使小增量不累积，故**B仍未排除**。N1短路发生在当帧fog buffer烘焙后，单独解释首帧std下降的证据弱。现有采集没有dirty/重烘逐帧次数。代码锚点：`P012WaterSandRenderer.ets` 的 buffer常量、`e3Invalidate`/`e3DrawFogBuffers`/降级上屏段，`P012E3FogBuffers.ets` 构造器，`tools/run_p012_e3_recheck.ps1` 的25秒等待。

## 2. A/B 归因裁决所需的 developer 回执

用 **s132同一构建、同一初态/seed/几何/输入、同一帧或预注册相位** 做最小配对，不跨构建比较截图均值来推断dirty频率。developer提供以下逐帧或逐有效物理步统计，首次必烘帧、冷启动后25秒沉降末帧、settle动态段、return段分列：

| 证据 | 至少需输出 | 解决的问题 |
|---|---|---|
| 缓冲失效账 | layer/waterTop/q/phase/palette/geometry各自请求dirty次数；`LAYER_EPS=0.25`拒绝次数和被拒绝时累计层高偏差；N1 bake请求/短路/实烘次数；buffer最大年龄；首帧与沉降后帧分列 | s132是否因阈值或短路漏掉可见材料变化；现行快照无条件更新是否造成永不累计 |
| 像素链账 | 当前物理快照hash、噪声场/seed/相位、I2计算alpha分布（均值、std、cap占比）、最终同ROI Y/std及构建/ROI/methodId | 分清光学幅度衰减、旧buffer和显示合成影响 |
| 同快照分辨对照 | 先固定N1 bakedPx=2，**同s132输入首帧必重烘，I2宽64 vs256**；分别报raw alpha、最终同ROI std、J/K与帧时；如确有需要加入128折中档 | 不让dirty差异干扰宽度/上屏分段因果判断；判定64采样是否直接压低std及恢复256的性能代价 |

**B（dirty策略）成立条件**：在相同输入下，强制重烘使最终ON/OFF std回到预注册警戒带，且实测到现行dirty漏更新；developer先修失效策略与性能回归，再由effector同冻结mask重新出数。须同时保留s132已恢复的帧时优势，不能简单回到每帧全图重烘。

**A（算法/采样面）成立条件**：同一首帧强制重烘下，宽64→256或N1 bakedPx2→1能实质恢复纹理，而仅改变dirty不恢复；或宽度/噪声采样保持时，I2计算alpha本身低方差。优先修复已发现的256→64采样偏离并测帧时；若主档256性能不能接受，由architect/developer提出等效连续采样或经证据支持的折中档，designer重新评估锚点适用性。只有排除分辨率欠采样并证实仍是光学幅度不足时，designer才给 `fogDensityScale>1` 或N1等效幅度的**候选**扫描，逐点检查纹理std、亮度、alpha饱和、J/K/P与SV-06自然度；不能预设倍率越大std越高，也不能改0.78/0.55硬上限。

若宽度和dirty都贡献差异、强制重烘后仍未回到警戒带，或原帧/ROI不匹配，则为**混合/证据不足**：按贡献顺序修复后重测，不能强行二选一宣布归因。两分支均不得以“OFF档位台阶被移除，std自然变小”为理由直接删掉已登记的防抹平保护项。

## 3. 正式锚点的测量缺口

现有复测的 `J95=0/4` 是设备侧纯雾带原生ROI的像素相邻差，支持“硬跳下降”的方向；它尚未给出设计稿主档200分析像素、敏感性100档、四参考帧同方法带。`K_ratio=0/.092` 仅为上边界每8px步的陡变占比，**不是**§2.2所定义的 marching-squares 全等值线每百像素弧长 `K90`。当前 `P64` 为行均值自相关，不能替代§2.2的像素域2D残差峰；lag64=-.62负峰不能当重复纹样正峰PASS。`Lgrid`、`Nseg` 尚无同方法输出。冻结mask只解决标注边界，不自动生成这五项的正式数值。

| 指标 | 当前可用数据 | 冻结前必须补齐 |
|---|---|---|
| J95 | s132原生设备ROI：OFF4、ON0 | 200主档/100敏感性，参考f0/f5/f2/f6及设备OFF/ON同一方法、有效像素对数、JPEG/尺度manifest |
| K90 | s132上边界`K_ratio`：OFF.092、ON0 | 按预注册等值线、角点聚类和弧长定义重算；参考与设备分列，无支持则N/A |
| P64/P256 | 行均值lag64、全谱描述 | 像素域横/纵滞后残差峰、支持像素对数、逻辑px到显示px换算；参考清水mask EMPTY→该cell N/A，不伪造参考带 |
| Lgrid | 无 | 设备原生128列边界/中心梯度比及分母支持；仅诊断，不与无同网格的参考硬比 |
| Nseg | 无 | 25/50/75%三线、4灰度主档及2/8敏感性档；描述性诊断，不设单向越小越好门槛 |
| std/SV-06 | 0.684超界；本次主观方向描述 | 修复后同输入OFF/ON配对回界；effector按冻结量表做正式SV-06对应项映射，既有SV-06=3不改写 |

参考带只从冻结参考帧及相同方法生成，按静态/动态和支持量分列；不以s132结果反向定界。f2雾mask上段的手/花过渡残留已由冻结revision登记，敏感性分析须说明其对上界的方向，不能暗改多边形。任何200/100px或极端参数组合导致结论翻转，状态记为 `COMPARABILITY_PENDING` 并交方法revision，不择优档位。
