# T69 触摸零源归因复盘 v1

日期：2026-10-26。designer；路线 `P051_TOUCH_TO_SOURCE_V1`。离线归因／条件设计交付，现场唯一根因未闭合；未实施／未真机复测，未标VALIDATED。

## 候选与选型

| 候选 | 取舍 | 决定 |
|---|---|---|
| 改NO_WATER／恢复或增高隐藏水 | T63原版已有隐藏水，且源事件入口存在确定平台契约缺口；改介质不能证明事件已达 | 拒绝；T59独立负责干场语义 |
| 减Pan slop或用每次Move强制start | 原页没有Pan门槛；每次begin会重置反突发clock，可能令每帧请求仍为0 | 拒绝，raw Down仅begin一次，静止hold由帧驱动 |
| 保留XComponent onTouch，再加父级回调碰运气 | 带libraryname的触摸走C侧，native分发为空；父级冒泡未有证明，重复接线又易双发 | 拒绝，不依赖该冒泡机制 |
| 新增native DispatchTouchEvent＋N-API有界输入桥 | 契约正确，可直接拿native local点；但需线程/队列/重建/终止/溢出/generation与单位协议，扩大T62/T68共享文件范围 | 可行备选，当前不选；未来确有架构需要则另版迁移，不能双入口 |
| 同内容区无绘制普通输入节点＋纯逻辑适配器 | 保留现有native renderer，避开libraryname事件限制；小范围页面/model hunk可测，raw触摸不依赖slop | 唯一推荐。输入节点无任何画面输出，所有内容仍走新shader |
| 自动生成源／每帧补沙作为“修复” | 会绕过真实手势，无法证明Up/Cancel和准入正确，掩盖问题 | 拒绝 |

## 证据对方案的约束

T63固定源码六文件已与归档逐字节匹配；主区已有干场等改动，不能拿主区解释旧包。零粒swap成功实证解决了尺寸启动门，但不证明触摸、F2投影、LAND或非空生命周期可用。

官方XComponent事件合同与native空callback构成确定接线缺口，现场没有逐事件追踪。因此方案修明确缺陷，同时要求补全Down→时钟→request→receipt→publication；不能把缺日志写成“收到0次事件”的设备事实。

所有39个model抽样都是sensor、shakeInput=0，仍不能推全程无stale或无摇晃。T71保留既有T50门槛，只报明确stop原因。原隐藏水和空气出生问题仍属于T58/T59，不与触摸修复合并。

用户最新要求禁止Canvas及背景前景回退。无绘制输入节点不是渲染替身；若后续需要可见触点，应在新shader内实现。旧页面背景合同由T68显式修订，不能为补事件顺手恢复历史Canvas。

## 暴露的缺口与后续

1. 模型自测直接start/tick可绿，但没覆盖平台事件入口；测试需把适配器到真实model联起来，并明确host不能证明ArkUI命中。
2. 注入receipt被忽略，缺少首拒诊断使输入失败和物理拒绝混为零源。
3. invalid start可沿旧坐标置touching、多指未锁主指、geometry默认尺寸可提前被用。集中在纯输入状态机内解决，避免污染物理。
4. T70到件后发现“快照模型”只固定两个入口文件，其余物理依赖仍来自已变化主区；正例支持模型可发源，不能充作完整T63物理链反证。A01记录床量0也不能表述为LAND通过。106是重叠阶段样本总计，独立抽样39条；保留原报告，designer明确证据边界。
5. 本轮新增T72独占被动日志／回执hunk；T71业务适配复用，不能两张卡同时改同一日志实现。T74不等待T71而先采现场，T69据首个失败阶段选T71实施分支。离线交付不解除设备事实这个实质前置，也不要求manager另加验收门。
6. 修复后先证明真实正源与松手停止，再开展边界投影/LAND/非空reset和后台。T59干场候选与T63湿场不同，设备对照须明确构建／介质revision；同一事件接线缺口可跨版本存在，但不能拼成同一run。
