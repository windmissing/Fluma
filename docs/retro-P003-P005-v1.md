# P-003 + P-005 v1 轮复盘

> 日期：2026-10-13　维护人：designer  
> 关联方案：`docs/algorithm-P003-P005.md` v1 / v2  
> 复盘范围：P-003 算法 v1 的候选探索、选型、守恒缺陷教训与 v2 改进方向。P-005 的客观/主观 RED 基线属于测试先行的可预见 `BLOCKED/NOT_IMPLEMENTED` 结果，本轮不作为实现失败归因，也不触发闭环判定。

## 1. v1 候选方案与选型

| 候选 | 当时思路 | 优点 | 风险/被否原因 | v1 结论 |
|---|---|---|---|---|
| 列标量三相 + 差速沉降 + 表层滑移 + 标量渗透 | 只维护 `waterTop/hs/hl/suspH/suspL`，用重沙更快沉降和轻沙更易扩散、扬起形成分区 | `O(N)`，内存小，适合端侧，易接入既有列标量架构 | 无法表达列内重沙穿过轻沙的相序变化；v1 用 `hl→hs` 伪造交换 | 选定，但 §3.3 后续被证明错误 |
| 禁用渗透，仅靠注入时序分选 | 重沙先沉降、轻沙后沉降，表层滑移扩大轻沙覆盖 | 实现最小、守恒容易 | 已混合沙堆缺乏二次分选；TC-WS-01 明确禁止把 `percolationRate` 置 0 绕过缺陷 | 备选，未采用 |
| 每列 K 层相标记账本 | 每层保存重/轻沙厚度，相邻层做等量对向交换 | 能精确表达混合带与多次分层 | `O(NK)`，内存和日志快照扩展较大，超出 v1 最小落地成本 | 推迟到后续候选 |
| 逐粒子 CA / 两流体耦合 | 直接模拟颗粒与流体 | 物理表现潜力最高 | 端侧耗时与内存不可控，难以稳定满足 100fps 与 `<2ms` 物理步 | REJECTED |

当时选型理由是优先满足列标量、低内存、低时延和平滑渲染。该目标正确，但 v1 没有把“分相守恒”作为所有状态转移的先验约束来审查，导致只检查了 `VH+VL` 总沙量，漏检 `VH` 与 `VL` 各自不变量。

## 2. 缺陷复盘

v1 §3.3 给出：

```text
hl[c] -= q
hs[c] += q
```

该公式试图表达“重沙下沉、轻沙上浮”，但在只有 `hs/hl` 两个厚度标量的状态表示下，它实际执行的是“轻沙相减少、重沙相增加”的物质转换：

```text
ΔVH = +q
ΔVL = -q
```

因此它只保持 `VH + VL`，不保持 `VH` 与 `VL` 各自守恒。TC-WS-01 的估算显示，即使只转移 `0.001H`，在 `VH0=VL0=0.1H` 时也会造成约 1% 分相漂移，远超 `<0.1%` 阈值。architect 将其标记为阻塞项并禁止 developer 实现，是正确防线。

根因：

1. 把“几何位置交换”误写成了“相厚度交换”。
2. 状态表示不完备：`hs/hl` 只有聚合厚度，没有记录列内垂直相序。
3. 守恒审计只停留在 §2.3 的声明，没有对每个动力学公式做逐相增量推导。
4. 候选方案评估未把“分相守恒”设为一票否决条件。

## 3. 实施与测试暴露的问题

- 尚未实现 v1，客观与主观报告为 RED 基线：`BLOCKED/NOT_IMPLEMENTED`。这是测试先行的预期状态，不代表实现失败，也不触发归因闭环。
- TC-WS-01 已把 §3.3 作为哨兵，要求 `percolationRate=6/s`，并禁止用置 0 或禁用事件绕过。
- 测试文档要求 `WS_SNAPSHOT` 可用模型状态重算总量；v2 若继续只用聚合 `hs/hl`，无法可靠重算垂直分选，因此必须追加相位剖面字段。
- 架构文档已明确 `percolationRate` 在 v1 阻塞期返回 `q=0` 并输出 `percolation_disabled_pending_designer`；v2 完成后该事件不得再作为正常路径。

## 4. v2 改进方向

1. **状态补全**：引入 `bh/bl/mh/ml` 四账本，分别表示有序重/轻层与混合表层；外部继续导出 `hs=bh+mh`、`hl=bl+ml`。
2. **等量对向交换**：重沙下移 `q+r` 时，轻沙通过 `q` 穿越交换与 `r` 成对分选保持同相总量不变。
3. **逐操作证明**：对沉降、渗透、滑移、扬起、倒立和水迁移分别给出 `ΔVH=0`、`ΔVL=0` 的增量证明。
4. **指标口径修正**：分选比改用相位剖面积分，阈值仍为 `separationRatio <= 0.5`。
5. **fallback 保留**：若混合带主观效果不足，v3 可评估 K 层账本，但仍必须通过分相守恒一票否决。

## 5. 经验沉淀

- 三相各自守恒是最高优先级不变量；任何“看起来像位置交换”的公式必须先做逐相增量审计。
- 状态表示必须能表达被模拟机制所需的自由度，不能要求两个聚合标量承载垂直相序信息。
- 测试哨兵要先于实现落地，并禁止用禁用机制、放宽阈值或降低参数来绕过。
- 端侧优化不能以牺牲物理不变量为代价，应优先寻找守恒且低复杂度的账本结构。

## 6. 2026-10-14 v2 外部评审追加复盘

### 6.1 暴露问题

- **参数未联立**：TC-WS-08 的 `peakSusp>=0.5` 与 `residualSusp<=0.05` 没有和 `liftRate/vH/vL/水深/时长` 一起核算。评审按 `E=1` 估算峰值约 2.4%；当前实现的持续输入稳态 `E≈45.5%`，实际峰值更低。
- **倒立余量不足**：默认 `vH=16/vL=6` 在 4 秒内沉积比例不足，`E=0.8` 还会继续对抗沉降。
- **浅水沉降无帧预算**：`depth→ε` 时一帧可清空悬浮沙；且重/轻两相分别限幅会叠加突破单帧 0.5 列。
- **事件语义含混**：算法采用跨 90° 事件切换，而 G3 写“连续 ±180°”、H06 写“数据模型被倒立分支改写→FAIL”，字面之间存在冲突。

### 6.2 v2.1 处理

- 参数组改为 `vH=64`、`vL=38`、`liftHRate=36/s`、`liftLRate=40/s`。
- 新增目标驱动 `shakeRampRate=8/s`，持续强摇晃约 0.125s 达到 `E=1`。
- 新增 `maxSandTopFrameDelta=0.48`，沉降、滑移、扬起共享同一整帧预算。
- 明确 90° 为事件式重力坐标系切换；H06 禁止渲染/UI 私改数据，不禁止经审计的 `invert180()`。
- 设计核算：TC-WS-08 峰值约 52.8%、残余约 0.54%；倒立 4s 重沙沉积约 94.5%、轻沙约 82.2%；`t90H/t90L≈0.636~0.643`。

### 6.3 非算法问题路由

- 场景一油水分层：接受评审意见，但属独立 P-001；建议 manager 另行开题，不由场景二方案兼容或预留。
- 签名通道：建议 manager 路由 developer/构建维护者；tester 在通道打通前保持 BLOCKED。
- 100fps 设备语义：建议 manager 同步 goals，tester 在低于 100Hz 显示环境输出 `N/A(environment_refresh_rate)`。
- 2D 表达力：算法已声明边界；建议 effector 按二维截面的颗粒/层次上限评分，manager 决定是否另立三维目标。

### 6.4 经验补充

- 时间阈值类指标必须与速率、几何、能量稳态和最坏帧步长联立核算。
- 限幅要按观测量建模：HG-04 约束的是整帧沙顶位移，不是单个算子的单次转移。
- “连续”需求必须定义到数学层面：连续显示/输入、事件式坐标切换、单一连续求解器是三种不同成本。

## 7. 2026-10-14 v2.1 复核续评与 v2.2 修订

### 7.1 复核结论

- **参数组**：`vH=64`、`vL=38` 通过可行域复核；外部复算峰值约 55%，与 v2.1 的 52.8% 方向一致，但距离 `>=50%` 阈值余量偏薄。
- **通量限幅**：v2.1 的 `maxSandTopFrameDelta=0.48 列/渲染帧` 机制方向正确，但表达错误——120Hz 等效 57.6 列/秒，超过 30 列/秒限速；30Hz 仅 14.4 列/秒，低于强摇晃需求，导致物理随刷新率变化。
- **核算口径**：v2.1 的 52.8% 峰值未显式处理“沉降 + 扬起共享预算绑定”。强摇晃期理论扬起约 21.9 列/秒，叠加沉降后超过预算，不能当作次要修正忽略。
- **语义闭环**：算法层已明确事件式倒立与 H06 解释，但 `docs/effect-cases.md` 的 H06 与 `docs/goals.md` 的 G3 仍为旧措辞，tester/effector 按字面仍可能判 FAIL。

### 7.2 v2.2 修订

- 将预算参数改为 `vSandTopMax=28 列/秒`；每个子步允许量为 `vSandTopMax * substepDt`，30/60/120Hz 下物理速率一致。
- 保留“沉降、滑移、扬起共享同一子步预算”的守恒限幅机制，只缩小转移量，不改变相位分配。
- 显式补充非绑定条件；TC-WS-08 强摇晃期预算会绑定，并按绑定重算。
- 明确 TC-WS-08 峰值目标区间为 `0.55~0.75`，避免压在 `>=0.50` 验收阈值边缘。
- 绑定核算结果：峰值约 `63.6%`，静置 8s 残余约 `0.70%`；`t90H/t90L≈0.633~0.635`。
- 倒立 4s 沉降核算：重沙约 `95.0%`，轻沙约 `83.1%`，总沉积约 `89.0%`。
- §3.2 追加说明：生产默认 `vH=64/vL=38`，重沙沉降速度约为轻沙 `1.68` 倍；原 `2.7` 倍仅属 v1 历史。

### 7.3 待 manager 路由

- `docs/effect-cases.md` H06：建议 manager 协调 effector 将措辞同步为“绕过 API 私改数组 = FAIL；经 `invert180()` 且通过守恒审计不判 FAIL”。
- `docs/goals.md` G3：建议 manager 明确采用“89° 连续 + 90° 事件式跨过”，或声明严格连续过 90° 需另立 v3。
- 实现侧：developer 需把 v2.1 的每帧定值预算替换为 v2.2 的 `vSandTopMax * substepDt`，并补充跨 30/60/120Hz 一致性单测。

### 7.4 经验补充

- 限幅参数必须使用与时间无关的物理单位（速率），不能把“每帧位移”误写成常量预算。
- 设计核算必须判断限幅是否绑定；绑定限幅不是次要修正，而是主导动力学的约束。
- 验收余量应有目标区间，不能只证明“刚好超过阈值”。

## 9. 2026-10-14 slopeLimit 姿态修正独立小修（v2.4）

### 9.1 路由结论

- manager 决策：`slopeLimit` 姿态修正作为独立小修立即处理，不并入 v3。
- 设计结论：历史 `abs(d)<=tan(α)` 只适用于 `tiltDeg=0`；倾斜时必须使用 `abs(d - tan(effectiveTiltDeg))>tan(α)`。
- 实施顺序：developer 先合入 v2.2，再实现 v2.4，避免同一 `WaterSandField.ets` 冲突。

### 9.2 v2.4 设计

- `relaxAngle` 改为相对重力目标坡面触发，donor/receiver 由 `deviation=d-tan(effectiveTiltDeg)` 的符号决定。
- 滑移继续调用 `splitTopV2`，接收端写入 `mh/ml`，保持重/轻/水三相严格守恒。
- 滑移计入 v2.2 每列共享子步预算；一次 `q` 滑移对 donor 与 receiver 各扣 `q`，不得绕过 `vSandTopMax=28`。
- 倾斜收敛判据改为 `max |d-tan(effectiveTiltDeg)|<=tan(α+2°)`；直立场景退化为原判据。
- tester 增加倾斜哨兵、边界不动作、直立回归、单子步预算、守恒与分选不回退断言。

### 9.3 经验补充

- 坡度阈值必须与重力坐标系一致；“绝对坡度”只是直立特例，不能当作通用不变量。
- 修正行为缺陷时仍要复用既有守恒账本与速率预算，避免为了修视觉问题引入瞬移或分相漂移。
- 小修也应写清 tester 可执行断言，防止实现只改条件、漏掉预算和指标口径。
