# T60 复盘：P051_RENDER_GATE_REPAIR_V1

日期：2026-10-26。designer；不使用真机。阶段：T52失败报告→静态归因→最小修复方案。设计交付完成，产品未验证。

F1最先暴露出“页面逻辑尺寸能直接当native像素”的隐含假设。进一步追踪发现首帧EGL尺寸为0时按逻辑量独立取整，会让比例guard在创建surface前拦截，从而形成重复拒绘。测量外层Stack而不是XComponent内容区，是另一个有源码依据但尚缺设备尺寸的风险。不能把两个风险合成已证实的T52具体像素差。

F2的上一次T49修改把Float32越域提前拒绝，确实避免了部分上传；但它只改变失败位置，没有解决合法Float64边界状态的可绘制表示。下一轮应同时验证源合法性和渲染表示可表达性，而不把INVALID_PARTICLE错误名当作物理事实。

候选路线及取舍：

| 候选 | 结论 | 原因 |
|---|---|---|
| 删除NONUNIFORM_SCALE或把epsilon改大 | REJECTED | 掩盖真实变换与来源错误，首次surface无尺寸的问题仍存在 |
| 保持旧逻辑路径，绑定正确子节点并建立DPI/光栅误差合同 | 可选，非首推 | 能修测量来源，但必须额外证明布局量化边界，不能凭猜测设容差 |
| 显式prepare真实surface + DEMO像素域入口 | 推荐 | 消除启动互锁与单位歧义，保留旧逻辑guard，原native frame已经要求像素 |
| 改物理边界epsilon/改坐标/丢弃坏点 | REJECTED | 为显示改变物理状态或丢失粒子，越过本卡职责 |
| 接受上传X=128或直接夹紧所有非法源 | REJECTED | 放宽native域并掩盖真正源错误 |
| 双精度/列内分段坐标新GPU布局 | 后备 | 可提高表达能力，但需改布局、native和shader，超出本次最小修复 |
| 严格验证Float64源后，显式版本的有界Float32渲染投影 | 推荐待T61反例冻结 | 只调整staging表示，源/质量/ID/状态不变，保留原native域并能给出误差上界 |

本轮保持了证据等级：T52真实拒绘、相同源文件身份和可证明的代码路径分别列明；设备那一帧的尺寸/slot未知，仍交T61或后续真机证据，不用合成夹具填补。主方案与工程任务书见 `docs/analysis-P051-T60-render-rejection-v1.md`。下一轮以同版本客观对照和修复后设备同用例为证，才能判断两个故障是否真正解除。
